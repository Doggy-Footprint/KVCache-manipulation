# Qwen3-4B 로컬 BBC 실험 1차 파일럿 (2026-11-06)

실험 1(prefix가 본문 KV에 남기는 흔적)을 사람이 쓴 BBC 기사 본문으로 Qwen3-4B-Instruct-2507에 돌린 기록이다. 계산은 로컬 M2(MPS)에서 했다. 계획한 100개 지문 중 25개를 처리한 뒤 사용자 요청으로 run을 멈췄고, 이 문서는 그 25개의 결과다. 실험 2(대화 주제 전환)는 이번 run에서 돌리지 않았다. 이전 4B 파일럿(합성 지문, H100)은 `reports/20261105-q3-4b-pilot/README.md`에 있다.

## 1. 요약

- **표본:** 지문 25개(5개 카테고리 × 5개), 설계 2개(bbc-v1, bbc-v2), 모든 지문에 헤드 단위 패칭 포함. 모든 표는 같은 25개 지문으로 계산했다.
- **표현 흔적은 이전 파일럿과 같은 크기다.** prefix를 바꾸면 같은 본문 토큰의 K/V/잔차 거리가 노이즈 플로어의 1.3–3.7배(레이어 최대값)다. 이전 파일럿은 1.3–3.9배였다. 본문 토큰만으로 페르소나/필러를 맞히는 프로브 최고 정확도는 0.93(v1)과 0.91(v2)이다. 우연 수준은 0.33이다.
- **힌트 효과는 중립 문장 N0와 크기로 구분되지 않는다.** v2에서 본문 끝 다음 토큰 KL(F1 기준) 중앙값은 H+ 0.020, H− 0.032, C+ 0.011, C− 0.016, N0 0.020이다. 지문별로 짝지은 차이(힌트 − N0)도 0에 가깝다(H+ +0.002, p=0.11). 페르소나만 N0보다 크다(P1 +0.051, p=2e−6).
- **다만 정답 헤드라인과 오답 헤드라인은 출력이 다르다.** H+와 H− 사이 KL 중앙값 0.024는 v2 플로어 0.006을 25개 지문 모두에서 넘는다. 카테고리 라벨의 정답/오답(C+ vs C−)은 0.007로 플로어와 거의 같다.
- **패칭에서 효과는 prefix KV에 실린다.** 기증자의 16토큰 greedy 이어쓰기 log-prob 기준으로 보면, prefix 구간 K+V가 이어쓰기 이득의 0.69–0.99를 재현한다. 본문 K+V는 헤드라인 힌트·페르소나에서 −0.01–0.09다. 예외는 카테고리 힌트 C±(본문 0.21–0.49)다.
- **이전 파일럿의 "오도 힌트는 본문 KV로 간다"는 재현되지 않았다.** 본문 끝 다음 토큰 KL 기준 회복률에서 H−의 본문 대 prefix 비율은 v1 −0.11 vs 0.58, v2 0.68 vs 0.65다. 이어쓰기 기준에서는 두 설계 모두 본문 0.04–0.09, prefix 0.88–0.89다.
- **이전 결과도 측정 지표에 따라 달라진다.** 이전 파일럿 패칭 행을 같은 이어쓰기 기준으로 다시 계산하면 H−는 본문 0.13–0.20, prefix 0.40–0.41이다. 이전 보고서의 본문 0.74–0.90은 다음 토큰 KL 회복률에서만 나온 값이다.
- **다음 토큰 KL 회복률은 이번 데이터에서 불안정하다.** 회복률이 정확히 0이어야 하는 대조 패치(레이어 0 본문)에서 v2 C±/F2의 |회복률| 중앙값이 0.13–0.15이고 최대 1.16이다. v2 H+ prefix 회복률은 −0.47 [−2.74, +0.83]인데, 같은 행의 이어쓰기 비율은 0.99다. 이 불일치의 원인은 확인하지 못했다.
- **비용과 시간:** 지문당 1218초(중앙값)가 걸렸고 GPU 비용은 없다. 원본 텐서 55.0GB는 Google Drive로 올렸고, 업로드 대기는 한 번도 없었다. 남은 75개 지문은 약 11시간으로 추정한다(추정 근거는 8절).

### 실험 1 조건

| 조건 | 내용 |
|---|---|
| F1, F2 | 중립 필러 두 개. F1이 기준, F1 vs F2가 노이즈 플로어 |
| H+ / H− | `The following passage has the headline "{headline}".` 정답 헤드라인 / 오답 헤드라인 |
| C+ / C− | `The following passage is about {label}.` 정답 / 오답 카테고리 라벨 (예: "business and the economy", "sport") |
| P1 / P2 | 회의적 변호사 / 공감적 상담사 페르소나 (이전 파일럿과 같은 문장) |
| N (v1만) | prefix 없음 (본문 위치가 달라 위치 통제가 안 된 조건) |
| N0 (v2만) | 중립 내용 문장 "The following passage is a news article." |

- 오답(H−, C−)은 다음 카테고리의 k번째 기사에서 가져온다. 예: business의 k번째 기사의 오답은 entertainment의 k번째 기사 헤드라인/라벨이다. 오답도 사람이 쓴 헤드라인이다.
- 이전 파일럿의 힌트 문형("The following passage is about {topic}.")은 이번 C±와 같은 문형이다. 이번 H±는 헤드라인 문형으로 새로 넣었다.
- **설계 bbc-v1** (`data/exp1_prefixes_bbc.json`): 필러는 날씨/도서관에 관한 긴 문단을 prefix 길이에 맞춰 자른 것이다. 다른 조건은 공통 패딩("Please read the text below." 반복) 뒤에 지시문 한 문장이다.
- **설계 bbc-v2** (`data/exp1_prefixes_bbc_v2.json`): 필러도 한 문장("The weather today is mild." / "The library opens at nine.")이고, 모든 조건이 "공통 패딩 + 완결된 한 문장"이다.
- prefix 길이는 25개 지문 모두 28토큰이다. 가장 긴 P2 문장(28토큰)에 맞춰 왼쪽을 패딩으로 채운다. H±/C± 문장은 7–19토큰이므로 패딩이 9–21토큰 붙는다.
- **두 설계는 F1, F2, N/N0만 다르다.** H±, C±, P1, P2의 prefix 토큰은 100개 지문 모두에서 두 설계 간에 같다(토크나이저로 확인). 이 조건들의 본문 끝 logits도 두 설계 간에 비트 단위로 같다(25개 지문 × 6조건). 따라서 두 설계의 차이는 기준(F1)과 플로어(F2)뿐이다.

### 4.5 회복률 지표 점검: 수치 잡음과 이어쓰기 기준 비율

1. **페르소나의 출력 효과는 prefix KV를 직접 읽어 생긴다. 이전 파일럿과 같다.**
   - 두 지표, 두 설계 모두에서 prefix K+V가 0.98–0.99를 재현하고 본문 K+V는 0.10 이하다.
   - 데이터가 바뀌어도(합성 → BBC) 이 결론은 같다.
2. **헤드라인 힌트도 이어쓰기 기준으로는 prefix KV가 운반한다.**
   - H±의 이어쓰기 이득은 prefix만으로 0.88–0.99, 본문만으로 0.03–0.09다.
   - 이전 보고서가 이례로 기록한 "오도 힌트는 본문 KV" 결과는 이 데이터와 이 지표에서 나타나지 않는다.
   - 이전 데이터에서도 그 결과는 다음 토큰 KL 회복률에서만 보인다. 이어쓰기 기준으로 보면 이전 H−는 본문(0.13–0.20)보다 prefix(0.40–0.41)가 크고, 어느 쪽만으로도 재현되지 않는 부분이 남는다.
   - 따라서 "오도 힌트 경로"라는 이전 관찰은 readout 첫 토큰 하나에 한정된 현상일 가능성이 있다(가설).
3. **내용이 적은 prefix일수록 본문 KV 비중이 커 보인다.**
   - C±와 F2는 전체 구간 패치의 이어쓰기 이득이 3.6–21 nats로 작다. H±/P는 67–79 nats다.
   - 이 조건들에서는 본문 K+V 비율이 0.16–0.77로 높다.
   - 효과가 작을 때 본문으로 번진 작은 차이가 상대적으로 커지는 것으로 보인다(가설). 예를 들어 C± prefix는 28토큰 중 패딩이 대부분이다.
4. **힌트의 "의미"는 크기로 분리되지 않는다.**
   - v2에서 힌트의 KL은 N0와 같거나 작다.
   - N0 대비 표현 거리는 문형 유사도(C±가 N0에 가장 가까움)를 따른다.
   - 힌트 방향은 지문 간에 null보다 일관되지 않다.
   - 다만 정답/오답 헤드라인은 서로 다른 출력을 낸다(KL 0.024, v2 플로어 대비 25/25). 이 차이가 헤드라인의 "맞음"에서 오는지, 단지 다른 문자열이라서 생기는지는 이 설계로 가를 수 없다. 오답도 실제 다른 기사의 헤드라인이기 때문이다.
   - 카테고리 라벨은 정답과 오답의 출력 차이(0.007)가 플로어 수준이다.
5. **CacheBlend류 캐시 재사용에 대한 함의는 이전 보고서와 같은 방향이다.** prefix 없이 계산한 본문 KV를 재사용해도 이어쓰기 기준 손실은 작다(H±/P 본문 비율 ≤0.09). C±에서는 손실이 0.21–0.49로 더 크다.

## 7. 한계

1. **n=25.** 계획한 100개 중 25개이고 카테고리당 5개다. 카테고리별 수치는 해석하지 않았다. p값은 다중비교 보정 없이 참고로만 적었다.
2. **MPS 단일 장치.** H100과의 행 단위 차이(v2 0.07–0.08)가 이번 v2 C±/F2 레이어 0 잡음(0.13–0.15)과 같은 크기다. 이번 숫자를 다른 장치의 run과 섞을 수 없다.
3. **readout은 첫 토큰 하나와 greedy 16토큰 이어쓰기뿐이다.** 다음 토큰 KL 회복률의 분모는 저장하지 않았다. v2 H+ prefix의 두 지표 불일치는 원본이 없으면(원본은 Drive에 있다) 진단할 수 없다. 이어쓰기 비율은 기증자의 greedy 이어쓰기 하나에 대한 값이고, 전체 구간 패치 값으로 나누므로 그 값이 작은 행(v2 F2 중앙값 3.6 nats, 최소 −0.13)에서는 불안정하다.
4. **BBC 저작권과 사전학습 오염 가능성.** 기사는 2004–05년 BBC 기사이고 명시적 라이선스가 없다. 데이터 파일은 이 로컬 저장소에만 둔다. 기사와 헤드라인이 모델의 사전학습 데이터에 들어 있었을 가능성이 높다. 헤드라인 힌트 효과의 일부는 기억된 (헤드라인, 본문) 쌍에서 올 수 있다(확인 안 함).
5. **문형 차이.** 헤드라인 문형("has the headline ...")은 이전 합성 힌트 문형과 다르다. 카테고리 라벨은 5개뿐이고 지문 내용보다 넓은 범주다. 오답 짝은 "다음 카테고리의 k번째"로 고정되어 있어, 오답 카테고리가 지문 카테고리에 따라 정해진다.
6. **추출 선택은 한 번뿐이다.** 지문은 seed 0 한 번의 표집이고, 힌트·페르소나 문구는 한 세트다. 같은 설정을 반복한 run은 없다.
7. **v1과 v2는 독립된 반복이 아니다.** H±, C±, P 입력이 두 설계에서 같아서 두 설계 간 차이는 기준(F1)과 플로어(F2)에서만 온다.
8. 노트북 그림의 패칭 곡선과 막대는 평균±표준편차다. 표는 중앙값과 사분위다. 분모가 작은 행(|r| 최대 21.5)이 평균을 끈다.

## 9. 재현

```bash
RUN=runs/exp1-100p-4b/main
REP=reports/20261106-bbc-4b-local-pilot1
W=<임시 폴더>
# 1) 완료된 25개 지문으로 통계·패칭 입력을 한정 (원본 run 폴더는 건드리지 않음)
tr ' ' '\n' < $RUN/order.txt | head -25 > $W/pids.txt
for d in bbc-v1 bbc-v2; do
  mkdir -p $W/stats/$d
  for p in $(cat $W/pids.txt); do ln -sf $PWD/$RUN/stats/$d/$p.{json,safetensors} $W/stats/$d/; done
  for s in exp1_patch exp1_patch_prefix; do
    mkdir -p $W/patch/$d/$s
    python3 -c "import json,sys; k=set(open('$W/pids.txt').read().split()); [sys.stdout.write(l) for l in open('$RUN/patch/$d/$s/results.jsonl') if json.loads(l)['passage'] in k]" > $W/patch/$d/$s/results.jsonl
  done
done
# 2) 요약 JSON (거리 비율, KL)
for d in bbc-v1 bbc-v2; do uv run python -m kvmeaning.summary $W/stats/$d $REP/data/summary_$d.json --stats; done
# 3) priming 노트북 (설계당 약 170초, 최대 RSS 4.8GB)
cd notebooks
for d in bbc-v1 bbc-v2; do
  KV_STATS=$W/stats/$d KV_FIG=../$REP/figures/$d uv run jupyter nbconvert --to notebook --execute exp1_priming_stats.ipynb \
    --ExecutePreprocessor.timeout=-1 --output-dir ../$REP/notebooks --output exp1_priming_stats__$d.ipynb
done
# 4) 패칭 노트북: 원본 노트북의 DONORS 줄만 7개 기증자로 바꾼 사본을 실행 (원본 노트북은 바꾸지 않음)
for nb in exp1_patching exp1_patching_prefix; do for d in bbc-v1 bbc-v2; do
  python3 -c "import json; n=json.load(open('$nb.ipynb')); o=\"DONORS = ('H+', 'H-', 'P1', 'P2', 'F2')\"; [c.update(source=''.join(c['source']).replace(o, \"DONORS = ('H+', 'H-', 'C+', 'C-', 'P1', 'P2', 'F2')\").splitlines(True)) for c in n['cells']]; json.dump(n, open('../$REP/notebooks/${nb}__$d.ipynb','w'), indent=1)"
  KV_RUN=$W/patch/$d KV_FIG=../$REP/figures/$d uv run jupyter nbconvert --to notebook --execute --inplace ../$REP/notebooks/${nb}__$d.ipynb
done; done
cd ..
# 5) 보고서 수치 (중앙값/사분위, 조건 간 KL, 대조 패치, 이어쓰기 비율, 이전 파일럿 재계산, 처리 시간)
uv run python $REP/analyze.py --stats-root $W/stats --patch-root $W/patch --run-dir $RUN --summary-dir $REP/data \
  --passages data/exp1_passages_bbc.jsonl --old-pilot runs/modal_pilot/20261105-173626 \
  --out $REP/data/numbers.json --fig $REP/figures/patch_metrics.png
# 6) 판정 J1–J4는 analyze.py가 kvmeaning.pilot.judge로 계산해 numbers.json의 "judge"에 넣는다.
```

- 실행된 노트북의 출력에 찍힌 통계 경로는 작성 시점의 임시 폴더다.
- 이어서 run을 계속하려면 `NAME=main scripts/local_exp1.sh --only $(cat runs/exp1-100p-4b/main/order.txt) --deadline <YYYY-MM-DDTHH:MM>`를 쓴다. 이미 끝난 단계는 건너뛴다.
